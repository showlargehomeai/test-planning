## 1.2 關鍵 API Endpoint 映射不一致

❌ 【嚴重】/sop 頁面 → API 實際不可達
   MAP 聲稱: /sop → interaction-service 的 /api/v1/sop-templates, /api/v1/sop-checklists
   實際情況: interaction-service 的 SOP 路由在 main.py 中全部 COMMENTED OUT：
     - app/routers/sop.py (原始版) — 被註解 (# app.include_router)
     - app/api/v1/sop_routes.py — 被註解 (# from .sop_routes import)
     - app/api/sop_routes.py — 完全未被 include
   前端 sop.ts 呼叫 /api/v1/sop-templates (flat URL)
   profile-service 有 SOP 在 /api/v1/sop/templates (nested URL，多一層 /sop/)
   → 前端 URL 和 profile-service URL 格式不匹配！
   → 結論: /sop 頁面的 API 端點在所有後端服務中都無法正確對接

❌ 【嚴重】/homeowner/dashboard → GET /api/v1/projects/my 不存在
   MAP 聲稱: interaction-service 有 GET /api/v1/projects/my
   實際情況: interaction-service 只有 GET /api/v1/projects (列表)，沒有 /projects/my
   前端 homeowner-dashboard.ts 確實呼叫 /api/v1/projects/my
   → 此 endpoint 後端不存在

❌ 【嚴重】/revenue → 多個 commission/revenue endpoints 不存在
   MAP 聲稱: GET /api/v1/commission/revenue/stats, /transactions, /monthly, /targets
   實際情況: interaction-service commission.py 只有:
     - GET /api/v1/commission/revenue/summary (不是 /stats)
     - GET /api/v1/commission/settings (CRUD)
     - POST /api/v1/commission/calculate
     - GET /api/v1/commission/types
   缺少: /revenue/stats, /transactions, /monthly, /targets, /participants/revenue
   前端 revenue.ts 呼叫 6 個端點，後端只存在 1 個（且名稱不同）

❌ 【嚴重】/weekly-digest (3頁) → 後端 API 完全不存在
   MAP 聲稱: product-service 有 GET /api/v1/weekly-digest/*
   實際情況: product-service 中完全沒有 weekly-digest 相關的路由或檔案
   所有後端服務 (product/interaction/profile/auth) 均無此 endpoint
   前端 weekly-digest.ts 有完整 API 定義但帶 USE_MOCK 開關
   → MAP 的聲稱完全錯誤

❌ 【中等】GET /api/v1/notifications → 路由未被 include
   MAP 聲稱: interaction-service 有 GET /api/v1/notifications
   實際情況: rfq_notifications_api.py 有此路由定義，但 main.py 中 NEVER include
   只有 notification_preferences_router 被 include
   → notifications 列表端點不可達

❌ 【中等】/gallery → 兩個 service 都有同路徑！
   MAP 聲稱: /gallery → profile-service 的 /api/v1/gallery/portfolios
   實際情況: BOTH profile-service AND interaction-service 都有:
     - router = APIRouter(prefix="/api/v1/gallery")
   兩者端點有部分重疊（如 /portfolios, /stats）和部分不同
   → 存在 API 路徑衝突風險（依 Nginx 路由決定打到哪個服務）

⚠️ 【注意】/projects/[id]/batch-inquiry → 後端完全沒有實作
   MAP 聲稱: POST/GET /api/v1/projects/{id}/batch-inquiries
   實際情況: interaction-service 中無任何 batch-inquiry/batch_inquiry 相關路由
   前端 batch-inquiry.ts 有 USE_MOCK 開關
   MAP 標注了 [WARN] 但低估了問題——不是「可能未完整」而是「完全不存在」

⚠️ 【注意】/designer/[code]/reviews → 只回傳空陣列
   MAP 正確標注了 TODO，實際 profile-service designer_public.py 確認:
   get_designer_reviews() 直接 return [] （硬編碼空陣列）
