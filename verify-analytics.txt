二、MD 寫了但有誤（3 處）

  → 漏了 service 和 docs 欄位

[錯誤-2] WARN 項目描述不精確

          but _get_default_stats includes them — schema mismatch"
  Code: _get_default_stats() 的 last_30_days 包含 materials_exported
        但 **不包含 favorites**
  → MD 說 "includes them"（暗示兩者都有）不準確，只有 materials_exported 是 mismatch

[錯誤-3] VendorStatsResponse json_schema_extra 範例遺漏 materials_exported
  MD: StatsDetail 列了 materials_exported 欄位
  Code: VendorStatsResponse 的 json_schema_extra example 的 total 沒有 materials_exported
  → 不影響功能（Pydantic default=0），但文件和 code example 有落差

三、MD 漏了（Code 有但 MD 沒提到）（4 處）
================================================================================

[遺漏-1] Cosmos container table 只列 read access，未提及 write access
  vendor_summaries: code 有 upsert_item（upsert_vendor_summary 方法用）
  vendor_daily_stats: code 有 upsert_item（upsert_daily_stats 方法用）
  → table 的 "Access" 欄只寫 read_item/query_items，遺漏 upsert_item

[遺漏-2] AnalyticsCache 的重連邏輯未提及
  Code: _get_redis() 每次 ping 失敗會 self._redis = None 重建連線
  MD: 只說 "graceful degradation"，未描述重連機制

[遺漏-3] AnalyticsCache 參數命名問題未提及
  Code: AnalyticsCache 所有方法參數都叫 vendor_id，即使 designer cache 也用同名
  → designer_analytics_cache.get(designer_id) 實際傳的是 designer_id，
     但方法簽名寫的是 vendor_id，易混淆

[遺漏-4] mock_cosmos.py 的 CosmosResourceNotFoundError 和實際引用不同源
  Code: stats_service.py import from azure.cosmos.exceptions.CosmosResourceNotFoundError
  Code: mock_cosmos.py 自定義了同名 class 但完全未被引用
  MD: 只說 "mock_cosmos.py exists but unused"，未說明有命名衝突
